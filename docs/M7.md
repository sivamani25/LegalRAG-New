# M7 — API + Frontend

Evidence-grounded LegalRAG API (FastAPI) plus a single-page frontend. Retrieval is
**category-aware**: every question is fanned out across the Acts, Constitution, and
Judgments indexes and merged by rank (RRF). Generation uses **OpenRouter only**.

## Endpoints
| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | liveness + configured categories |
| POST | `/chat` | grounded answer + citations/metadata + related cases + limitations |
| POST | `/chat/pdf` | the same answer as a downloadable PDF |
| GET | `/eval` | live retrieval metrics via `legalrag.eval.runner` (no rebuild) |
| GET | `/` (and `/static/*`) | single-page frontend |

`POST /chat` body: `{ "question": "...", "conversation_history": [ {"role":"user|assistant","content":"..."} ] }`

## Setup
1. Install dependencies:
   ```powershell
   .\.venv\Scripts\python.exe -m pip install -e ".[dev]"
   ```
2. Create `.env` in the project root (never commit it):
   ```
   OPENROUTER_API_KEY=sk-or-...
   ```
   Generation models are read from `config.yaml` (`cohere/north-mini-code:free`, fallback
   `poolside/laguna-xs-2.1:free`). Ollama is not used.

## Run
```powershell
# uses app.host / app.port from config.yaml (default 127.0.0.1:8000)
.\.venv\Scripts\python.exe -m legalrag.app.main

# or
.\.venv\Scripts\python.exe -m uvicorn legalrag.app.main:app --host 127.0.0.1 --port 8000
```
Open http://127.0.0.1:8000/ for the frontend.

## Exercise
```powershell
Invoke-RestMethod http://127.0.0.1:8000/health

$body = '{"question":"What does Article 21 of the Constitution guarantee about life and personal liberty?"}'
Invoke-RestMethod -Method Post http://127.0.0.1:8000/chat -ContentType 'application/json' -Body $body
Invoke-WebRequest -Method Post http://127.0.0.1:8000/chat/pdf -ContentType 'application/json' -Body $body -OutFile answer.pdf

Invoke-RestMethod 'http://127.0.0.1:8000/eval?k=1,3,5,10'
```

## Notes / limitations
- The retrieval bundle (three SentenceTransformer-backed retrievers) and the OpenRouter
  client are built **lazily** on the first `/chat`, `/chat/pdf`, or `/eval` request, so the
  app starts fast. **Expect ~1 minute for the first request** (model load plus a one-time
  byte-offset scan of the Judgments corpus); later requests are fast and `/eval` (live over
  all 30 cases) takes a few minutes.
- Retrieval is **federated**: every question queries all three category indexes and results
  are merged by rank (RRF). Rank ties are broken toward the category with the stronger
  internal match, so a weakly-matching category does not outrank a strongly-matching one.
- **PDF export** (`POST /chat/pdf`, and the frontend *Download PDF* button) renders the exact
  `/chat` response (answer, cited authorities, related cases, limitations) with a
  dependency-free PDF writer. It never includes secrets.
- Full evidence text is read via `CorpusTextStore` byte-offset sidecars written under
  `data/cache/text_offsets/` (never inside the corpus or index directories). The first request
  that touches judgments builds that sidecar by scanning the corpus once.
- **Citations**: the prompt requests square-bracketed `[S1]` labels, and parenthesised labels
  such as `(S1)` are normalized to `[S1]` before validation and rendering. The verifier
  checks only **citation labels** against the supplied passages (`support_verified` is always
  `false`); unknown labels such as `[S9]` are flagged. Substantive legal support is never
  asserted as verified.
- No secrets are exposed: `/chat`, `/chat/pdf`, `/eval`, and the frontend never return
  `OPENROUTER_API_KEY`.
- Errors: empty/blank question → 422; missing key / generation failure → 503; retrieval
  failure → 502.
